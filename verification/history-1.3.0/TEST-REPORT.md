## 三个实际 UX 问题的回归证据

### 1. 表单字段事务与撤销

- 卡片表单逐字符 ux-demo → ux-edited，失焦并点大纲后，一次工具栏撤销恢复 ux-demo，一次重做恢复完整 ux-edited；字段内 Ctrl+Z/Y 使用同一文档历史。
- 紧凑输入同样分组；重新聚焦形成新步骤。不同字段、源码输入、保存基线、文档切换、导入隔离；失效会话令牌不能改写新文档。
- 全 App DOM 集成不 mock 源码编辑器，验证真实 React、store、CodeMirror 双向同步不会把一次表单输入拆成多个历史步骤。补验输入法组合状态下不抢文档撤销快捷键；未做完整系统 IME 矩阵。
- 无效数字临时缓冲不在 blur 时把过时值重新写回文档；外部撤销/重做可刷新字段显示。

### 2. 语义错误真实位置与导航

- 核心测试校验未定义别名在真实第 5 行、精确 token 范围，多文档仍为整文件第 5 行；不安全标量、未知标签、EOF 范围也检查，不重复制造标签诊断。
- 未知位置（例如通用循环引用解析失败）显示「位置未知」，不能伪造首行；旧源码上的定位请求被拒绝。
- 实际 TestPanel 组件点击、Enter/空格激活，以及真实 CodeMirror 联动选中 *missing、保留原文、多文档偏移。完整 App 集成验证原先显示表单的工作区切回源码。
- DOM 测试不能替代真实视口渲染、滚动像素、点击遮挡与辅助技术体验验证。

### 3. Web 下载副本 / 原生保存的环境语义

- Web 工具栏/文件菜单统一「下载副本」，移除工具菜单重复另存为；Ctrl+S、Ctrl+Shift+S 触发同一导出行为并保留 dirty。组件验证导出下载发起，不证明浏览器落盘。
- 原生桥接组件验证保留「保存 / 另存为」两条动作与原生路径调用；Web 快捷键处理器不截获原生环境。
- 完整 App 集成验证：未保存时新建弹确认；发起下载后不自动离开；取消保留原文；明确确认成功才继续。不是静默清除未保存保护。

## 保留的限制与安全退化

- 导入/原生保存上限 2MiB；解析另有限制：2Mi 字符、10000 行、200 文档、60 层、20000 节点、100 次别名展开等。复杂 YAML 保留源码，但不承诺完整可视化；部分语义失败仅列首个问题，逐个修复后继续检查。不能确认的错误范围不强行定位。
- 历史每方向最多 200 步且约 8MiB；同一字段在一次聚焦期间的输入视为一次事务，重新聚焦才是新组，不是无限日志。大 Diff 使用区块回退、最多预览 3000 行。主 JS 仍约 1MB，构建有体积提示。
- Schema 拒绝执行型正则和远程 ref；JSON 应用可能丢本活动文档注释/锚点，有提示且可撤销。转换不是任意 YAML 的无损往返。
- Web 下载不等于已写回原文件，不能自动确认落盘；刷新/关闭确认受浏览器策略限制。本地存储不加密、不是备份；配额/清除/断电/强杀恢复不保证。
- 原生保存是最终检查加原子替换，不是跨进程排他锁，仍有非协作外部写入极短竞态窗口。1.3 已完成 Windows 交叉打包与实际载荷校验，但未签名、未实机运行。
